## 1. 背景与目标

### 1.1 背景

钉钉悟空（Wukong）背后的 DEAP 网关提供多模型能力（通义千问、Claude、GPT），但其协议要求一整套业务头（`x-dingtalk-*`、`x-wukong-*` 等），普通 OpenAI 客户端无法直接调用喵～

xrl-router 是一个统一的 LLM 路由层，负责密钥管理、请求分发、重试逻辑；它通过插件机制扩展对不同协议的支持喵～

### 1.2 目标

让任何能调 OpenAI API 的客户端（Claude Code、Cursor、各类 IDE 插件）通过 xrl-router 无缝访问 DEAP 网关，无需感知 DEAP 协议细节喵～

### 1.3 非目标

- 不实现 Anthropic Messages API 协议（那是旧版架构，已废弃）
- 不管理密钥轮转逻辑（由 xrl-router 负责）
- 不运行任何本地模型

## 3. 用户故事

### US-1：开发者接入 DEAP

**作为** 使用 Claude Code 的开发者，  
**我希望** 配置 xrl-router 指向本插件后能直接调用 DEAP 模型，  
**以便** 我不需要修改任何客户端代码就能使用通义千问/Claude/GPT 喵～

**验收标准：**
- 客户端发送标准 OpenAI Chat Completions 请求
- 插件自动注入 DEAP 业务头并转发
- 响应格式符合 OpenAI 协议（JSON 或 SSE 流式）

### US-2：密钥池管理

**作为** 运维人员，  
**我希望** 能在 `.env` 中配置多个 DEAP 密钥，  
**以便** xrl-router 能自动轮转，避免单密钥配额耗尽喵～

**验收标准：**
- `.env` 中 `WUKONG_KEYS` 支持逗号分隔多个密钥
- 插件每 5s 轮询 `.env`，检测变化后推送给 xrl-router
- xrl-router 在请求时自动轮转密钥

### US-3：一键抓密钥

**作为** 首次使用的用户，  
**我希望** 运行 `pnpm capture-key` 就能自动抓取 DEAP 密钥，  
**以便** 我不需要手动配置 mitmproxy 和系统代理喵～

**验收标准：**
- 脚本自动完成：起 mitmdump → 开系统代理 → 触发 daemon → 抓 key → 校验 → 写 `.env` → 还原代理
- 跨平台支持（macOS + Windows）
- 失败时保留日志供排查，成功时焚毁含明文 key 的日志

### US-4：故障自动恢复

**作为** 运维人员，  
**我希望** 插件断线后能自动重连，  
**以便** 我不需要手动重启服务喵～

**验收标准：**
- WebSocket 断线后自动重连（指数退避，最大间隔 60s）
- 心跳保活（每 30s 一次）
- 重连成功后自动重新注册并推送当前密钥池

## 4. 功能需求

### 4.1 核心功能

| 编号 | 功能 | 优先级 | 描述 |
|------|------|--------|------|
| F-1 | DEAP 协议桥接 | P0 | 接收 OpenAI Chat Completions 请求，注入 DEAP 业务头，转发到 DEAP 网关 |
| F-2 | 流式支持 | P0 | 支持 `stream: true`，透传 SSE 字节流 |
| F-3 | 非流式支持 | P0 | 支持非流式请求，透传 JSON 响应 |
| F-4 | 密钥池推送 | P0 | 轮询 `.env`，检测 `WUKONG_KEYS` 变化后推送给 xrl-router |
| F-5 | WebSocket 注册 | P0 | 启动时连接 xrl-router 并注册为插件，推送模型列表和密钥池 |
| F-6 | 心跳保活 | P1 | 每 30s 发送心跳，保持连接 |
| F-7 | 断线重连 | P1 | 指数退避重连（基础 1s，最大 60s） |
| F-8 | 一键抓密钥 | P1 | `pnpm capture-key` 跨平台抓取 DEAP 密钥 |

### 4.2 辅助功能

| 编号 | 功能 | 优先级 | 描述 |
|------|------|--------|------|
| F-9 | 健康检查 | P2 | `/health` 端点，轻量级探测（不发请求到 DEAP） |
| F-10 | 服务信息 | P2 | `/` 端点，返回版本、后端、模式等信息 |
| F-11 | 端口释放 | P2 | 启动前自动检测并释放被占用的端口 |

## 5. 非功能需求

### 5.1 性能

- 请求延迟：插件层增加延迟 < 10ms（不含网络传输）
- 内存占用：单实例 < 100MB
- 并发能力：单实例支持 100+ 并发请求

### 5.2 可用性

- 断线自动重连（指数退避，最大间隔 60s）
- 心跳保活（每 30s 一次）
- 优雅退出（SIGTERM/SIGINT 时关闭 WebSocket 连接）

### 5.3 安全性

- `.env` 与密钥永不进 git（`.gitignore` 强制）
- 抓包日志含明文 key，成功时即焚、失败时保留供排查
- 系统代理用完必还原（脚本在 finally 里保证）
- 仅对本机、本人已登录悟空抓密钥（授权的本地分析）

### 5.4 兼容性

- Node.js ≥ 20
- 跨平台：macOS + Windows
- 协议兼容：OpenAI Chat Completions API（流式 + 非流式）

## 6. 约束与依赖

### 6.1 约束

- 本插件不管理密钥轮转逻辑（由 xrl-router 负责）
- 本插件不运行任何本地模型（全部能力来自远端 DEAP 网关）
- DEAP 网关要求一整套业务头（缺一会 400），且流式请求不能带 `Accept: text/event-stream` 头（会 406）

### 6.2 依赖

| 依赖 | 用途 | 版本 |
|------|------|------|
| xrl-router | 上游路由层，负责密钥管理和请求分发 | 必须运行在 `http://localhost:19068` |
| DEAP 网关 | 后端模型服务 | `https://api-deap.dingtalk.com/dingtalk/v1` |
| 钉钉悟空 App | 仅用于抓取 DEAP 密钥 | 须已在本机登录 |
| mitmproxy | 仅用于抓密钥 | `brew install mitmproxy` |

## 8. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| DEAP 密钥过期（约 29 天） | 服务不可用 | 一键抓密钥脚本 + 密钥池多密钥轮转 |
| xrl-router 断线 | 插件无法注册 | 自动重连（指数退避） + 心跳保活 |
| DEAP 网关 406 | 流式请求失败 | 不设 `Accept: text/event-stream` 头 + 注入必需字段 |
| 系统代理未还原（macOS） | 全局流量走代理 | 脚本 finally 保证还原 + 校验 server:port |
| daemon 未就绪 | 抓不到 key | preflight 检测 `service status` + 提示用户启动 App |
